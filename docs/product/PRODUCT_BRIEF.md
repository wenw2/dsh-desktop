# Product Brief

审计日期：2026-09-03。定位与范围来自本次产品要求；这是施工依据，不是已实现功能清单。

## 产品定位

**Task-first local Agent desktop workspace.**

面向个人的、本地优先的桌面 Agent 工作台。以 Workspace 中的实际任务为中心，让用户能够明确目标、讨论方案、批准必要操作、检查文件变更与交付物，并在中断后继续同一项工作。

DeepSeek Harness 继续提供唯一的 Agent Runtime。当前仓库提供 Electron 桌面宿主，并复用 Harness Web UI；不另写 Agent Loop，也不把聊天界面整体复制进桌面仓库。

“本地优先”指 Workspace、工作状态和用户数据优先留在本机，**不等于完全离线**。配置远程模型后，模型请求可能离开本机；现有插件、更新和手机桥接也有各自网络行为。第一版不改变这些安全、更新和凭证边界。

## 目标用户与核心任务

首要用户是使用 macOS Apple Silicon 的个人，需要让 Agent 在可理解、可批准、可检查的范围内处理本地工作。

优先任务：

- 读取已有项目，解释结构、问题、约束和实现方案。
- 在明确授权后执行文件编辑、命令和验证，并展示真实结果。
- 检查本次工作的文件变化、Diff 与交付物，决定保留或恢复受支持的变更。
- 中断后找回同一任务、方案、历史与执行状态，不重新解释全部上下文。

普通问答、知识讨论和通用聊天由 ChatGPT 承担。本产品不以聊天次数或消息长度衡量价值，而以一项真实任务能否安全闭环衡量价值。

## 为什么不是普通聊天客户端

聊天消息不足以表达“做了什么、操作了哪里、谁批准了什么、文件现在是什么状态”。本产品需要在对话之外建立以下可追溯关系：

| 核心对象 | 产品含义 | 与现有 Harness 的关系 |
| --- | --- | --- |
| Project | 有明确目录与工作边界的项目 | 引用 Harness Workspace；不迁移或复制项目文件 |
| Task | 有目标、范围与验收条件的一项工作 | 产品语义关联 Session；当前没有独立产品 Task 模型 |
| Run | Task 的一次可观察执行过程 | 可按 Session/Turn 事件派生；不是另一个调度器 |
| Plan | 用户审阅的行动方案 | 区分计划正文、Plan Mode 状态和 Todo 列表 |
| Tool Action | 一次有目标、状态和结果的实际工具调用 | 复用 Harness call/result 与 callId |
| Approval | 对具体动作与范围作出的授权 | 保留 Harness 既有审批；批准方案不等于批准全部工具 |
| Change | 可核对来源、前后状态和归属的文件变化 | 单工具 Diff 只是部分证据，完整 Change Set 尚未证实存在 |
| Deliverable | 可定位、可打开、能够回到执行证据的产物 | 不将模型提到的路径自动当成新生成文件 |

详细映射与能力限制见 [ARCHITECTURE_BOUNDARIES.md](ARCHITECTURE_BOUNDARIES.md)。

## Discuss 与 Work

| 维度 | Discuss | Work |
| --- | --- | --- |
| 用户意图 | 澄清问题、读取必要资料、比较方案、审阅 Plan | 执行已经明确授权的任务范围 |
| 主要结果 | 有依据的判断、范围与待确认方案 | Tool Actions、实际验证、Changes、Deliverables |
| 权限含义 | 讨论本身不授权文件变更或有副作用的命令 | Work 也不是无限授权，仍由现有权限与必要 Approval 约束 |
| 切换条件 | 用户决定进入执行阶段；模式状态需与 Runtime 一致 | 用户可以暂停、取消或退回讨论，但已经发生的副作用不会因此自动撤销 |
| 强制保证 | 若宣称只读，必须用既有 Harness 权限/沙箱能力证明 | 不绕过 Harness 执行与审批，不增加通用 Shell IPC |

**当前关键限制：Harness Plan Mode 是 guidance，不是 enforcement，所有工具仍可调用。** 因此，不能只把 `/plan` 或 Plan chip 改名为 Discuss 就承诺“不会改文件”。这属于 MVP 发布门槛，不能靠提示词、按钮颜色或免责声明替代验证。

依据：`@deepseek-ai/dsh-plan-mode@0.1.2-alpha.4` 的 `README.md` 与 `lib/types/index.d.ts`，详见 [UI_SURFACE_MAP.md](UI_SURFACE_MAP.md)。

## 第一版范围

保留完整闭环：

打开 App → 添加 Workspace → 新建 Task → Agent 读取项目 → 显示 Plan → 执行文件或命令操作 → 请求必要批准 → 显示 Changed Files / Diff → 用户接受或回滚 → Session 可以恢复。

这里的批准必须发生在相关受控副作用之前；流程中的排列不代表“先执行再补批准”。具体可测试标准见 [MVP_VERTICAL_SLICE.md](MVP_VERTICAL_SLICE.md)。

第一版不做：

- 通用聊天产品、社交、团队协作或云端同步平台。
- Browser / Computer Control、Automation 或后台自主工作系统；仅保留未来接入既有 Tool Action / Approval 的原则。
- 第二套 Agent Runtime、独立 Agent Loop、模型请求循环或工具调度器。
- 安全边界、Safe Mode、权限系统、更新系统、凭证存储的重写。
- 依赖升级、构建工具替换、打包框架迁移或全局软件安装。
- 对任意 Shell、网络、安装操作的通用“撤销”承诺。
- 为实现局部 UI 需求而先 Fork 整个 Harness 或复制整套 Web UI。

现有手机、插件管理、更新与恢复功能不因为“不新增”而被删除；保留原实现，不将它们扩张为第一版产品工作。

## 成功指标与发布门槛

下列是目标与测量方式，**不是本次测得的产品成绩**。

| 指标 | 目标 / 判定 | 测量方式 |
| --- | --- | --- |
| 未授权副作用 | 0；拒绝必要批准后，受控操作不派发 | 专用 fixture 的文件前后比对、工具与审批记录 |
| 闭环完整性 | 所有强制验收步骤通过，不能跳过回滚或恢复 | MVP 验收矩阵逐项保留证据 |
| 执行可追溯性 | 每个呈现为已执行的动作都有实际调用与结果来源 | Task/Session/Turn/callId 映射检查 |
| 变更与产物可信度 | 不把缺失证据显示为“无变更”或“已生成” | Diff、文件存在性和来源对照；无法归属明确标注 |
| 恢复正确性 | 覆盖正常结束、取消、审批等待、结果未知等断点 | 重启同一 Session；不自动重放有副作用的未知调用 |
| 受支持回滚正确性 | 精确恢复本任务受支持的文件集合，用户原有修改不丢失 | 前态/后态校验与并发修改负面测试 |
| 开始工作的成本 | 记录冷启动至主界面、创建任务至首次有效读取的时间 | 后续实测分布；本轮未测性能，不预填数字 |

优先级：授权与数据不丢失 → 状态真实可恢复 → Runtime 可升级 → 任务流程清楚 → 视觉优化。

## 当前决定与下一步

当前桌面宿主可以启动，但完整自动测试尚未全绿；本次没有实现上述产品功能。真实结果见 [BASELINE_AUDIT.md](BASELINE_AUDIT.md)。

下一轮建议先单独授权修复已定位的发布说明 tag 边界与测试隔离问题，恢复可用基线。首项**产品代码**建议是无副作用的 Product Adapter 类型与只读 projection 契约测试，再决定最小 UI 入口；不先做首页或 Work Panel。
